# Zombie-Woche: Auftritt, Biss und Wochenabschluss

Die Szene verwendet die vorhandenen Season-Avatare und Bildatlanten. Menschen stehen bereit; Zombies erhalten eine Farbänderung und die bereits vorhandene Ziehen-Pose mit ausgestreckten Armen. Die K.O.-Pose zeigt die kurze Benommenheit während der Verwandlung, die Jubel-Pose gehört den tatsächlichen Überlebenden. Es gibt keine neuen Bilddateien oder Laufzeitabhängigkeiten.

`animation.verlauf` liefert die chronologischen Spielstände, `animation.aktuell` den maßgeblichen Endstand. Patient Null ist vom Start an Zombie und bekommt einen eigenen Auftritt aus Nebel. Ein neu gemeldeter Biss wird mit Zurückweichen, Angriff, kurzer Trefferpause, Verwandlung und anschließendem Schlurfen inszeniert. Mehrere neue Bisse in einem Zeitabschnitt werden mit demselben Ereigniszeitpunkt einzeln dargestellt. Das Spiel speichert keinen Verursacher eines Bisses; der Angreifer ist deshalb ein unbenannter, dekorativer Schatten und kein erfundener Spieler-Verursacher.

Normales Training heilt niemanden, wenn der Server weiterhin einen Zombie meldet. Rückwirkende Einträge können den vom Server rekonstruierten Verlauf ändern. Entfernte Infektionen und Löschkorrekturen werden ruhig als Korrektur gezeigt, ohne Heilungs- oder zusätzlichen Angriffsablauf. Die Spiellogik, die Zwei-Tage-Regel und die Wertung werden nicht verändert.

Erst `animation.abgeschlossen` löst das Finale aus. Überlebende jubeln mit einem kurzen Konfettieffekt; bei vollständig infizierter Gruppe schlurfen die Zombies ohne Siegesfeier. Alle Spieler behalten ihren korrekten Status auf der scrollbaren Tribüne. Auf der Bühne erscheinen höchstens drei repräsentative Figuren, der eigene Avatar wird bevorzugt; das ist keine Rangliste. Leere Gruppen und ein nicht mehr bekannter Patient Null erfinden keine Figuren.

Beim ersten Öffnen wird der ganze gelieferte Verlauf erzählt. Aktualisierungen mit unverändertem Präfix spielen nur die neuen Abschnitte. Wird bei identischem Verlauf erstmals der Abschluss gemeldet, folgt nur das Finale. Veränderte oder verkürzte Zustandsfolgen werden neu erzählt. Eine bloß geänderte Abrufzeit bei gleichem Ereignistyp und Stand ist keine neue Station: Vor der Morgenmeldung bekommt der aktuelle Tagesstand vom Server bei jedem Abruf eine neue Zeit. Die angezeigten Zeitpunkte stammen weiterhin aus der jeweils aktuellen Antwort. Szenenwechsel, Überspringen, Hintergrundwechsel, Breitenänderungen und reduzierte Bewegung räumen eigene Animationen, Effekte und Wartezeiten auf. Reine Höhenänderungen wie die mobile Adressleiste unterbrechen die feste Bühne nicht. Die Tribüne bleibt statisch; im laufenden Endstand bewegen sich höchstens die drei großen Bühnenfiguren dezent. Abgeschlossene Spiele und reduzierte Bewegung bleiben ruhig.

Die Zombie-Szene besitzt einen eigenen Ablauf, damit eine Verwandlung vor dem nächsten Abschnitt fertig wird; die gemeinsame Laufzeit der anderen Minispiele bleibt unverändert. `zeichne()` beendet einen laufenden Zombie-Rückblick vor dem Austausch der Ansicht.

Eigenständige Vorschau: `npm run build && node scripts/zombie-vorschau.mjs /tmp/zombie-vorschau.html`. Dieselbe Szenenlogik und eingebettete Medien; Beispiele für laufenden Rückblick, einen/drei Überlebende, alle infiziert, Korrektur, Spielstart, 60 Spieler und leere Gruppe. Die Update-Schaltfläche startet dort ein neues Beispiel; in der Mini-App lädt sie den tatsächlichen Serverstand.
